# A small archive's digitisation pilot

## Begin with the collection question

A volunteer archive wants to make a selected set of local-history photographs easier to find. This is a proposed workflow, not a report of a completed programme. The pilot's question is whether each selected object can become a useful, traceable catalogue record without losing uncertainty about its identity or permissions. Faster scanning is not the only objective: an attractive preview with an unsupported date would make the catalogue less trustworthy.

The pilot begins with a deliberately limited batch chosen by the archive team. Each object receives a stable record identifier. A manifest records the physical location and the reason for inclusion. Selection is an editorial choice, not a random sample of every object in the archive; the final report must preserve that distinction.

## Route work by the requested service

An intake request may ask for a new scan, a correction to an existing description, or help locating an object. A coordinator selects the relevant service. A description correction does not automatically require rescanning, and a search request does not automatically create a new catalogue entry. When the service is unclear, the coordinator asks for clarification before assigning work.

This routing decision chooses a path. It is different from the two reviews required for a new catalogue entry, where both contributions are needed. The distinction matters because drawing every specialist as a branch from one input could otherwise imply that every specialist works on every request.

## Gather two independent notes

For an object entering the digitisation pilot, intake creates one record identifier and passes the same object description to two reviewers. A description reviewer returns an identity note: proposed title, approximate date where supported, and unresolved attribution. A permissions reviewer returns a permissions note: the basis for public display, restrictions, or an unresolved question. The notes can be prepared independently; neither reviewer decides the final catalogue status alone.

A catalogue editor receives both notes under the same identifier. The editor reconciles missing information and records the decision. A missing permissions basis cannot be replaced by a confident description, and a permission to display cannot settle who appears in a photograph. The join is therefore a decision with distinct required inputs, not simply a folder containing two files.

## Revise with a specific question

If a note is unclear, the editor returns a specific question to intake. Intake supplies an updated description or records that the answer is unknown, then requests the affected review again. The return message carries the unresolved issue; it is not a generic instruction to try harder. The editor may approve a record with an explicit uncertainty, keep it restricted, or stop the attempt pending more evidence. This proposal makes no claim that repeated review must eventually produce approval.

## Keep the record and preview together

The catalogue page presents the stable identifier, the approved description, visible uncertainty and the applicable display status. A concise preview may omit working discussion, but it must tell readers where the fuller record is available. An error message should identify the failed action and a useful next step. Merely making a message shorter does not improve it if the information needed for recovery disappears.

No actual scans, personal information or permissions decisions are included in this design exercise. The proposed interface is a teaching example. The archive would need to define its own operational criteria before using it.

## Report the pilot without changing the denominator

A report should distinguish selected objects, objects reviewed, and records approved for public display. A high approval share within the chosen batch would not establish a high approval share across the entire archive. The selected batch and the full collection answer different population questions. If comparisons are later published, each should state its denominator and selection process; no percentages are supplied here because the pilot has not been run.

## Close with a decision

At the end of the batch, the team can decide whether to revise the intake form, review responsibilities or catalogue presentation. The decision should use actual missing-information patterns and reviewer feedback. A diagram can make the handoffs inspectable, but it cannot establish that the process is accurate, efficient or ready to expand. The accompanying figures explain responsibility and message content without pretending to be evaluation results.
