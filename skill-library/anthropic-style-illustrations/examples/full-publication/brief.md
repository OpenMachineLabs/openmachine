# Choosing an exchange pattern

## Reader need

The publication recommends simple systems, with additional complexity justified by evaluation. Its patterns distinguish fixed dependencies, alternative handlers, concurrent contributions, dynamic decomposition and feedback. Interfaces and stopping rules remain important throughout.

## Selected explanation

A router chooses a specialist. A parallel workflow combines independent contributions. An evaluator returns actionable critique and permits an accepted result to leave the cycle. Similar boxes can therefore imply different contracts.

## Scope

This original comparison teaches those contracts. It does not rank models, promise convergence, estimate speed or replace the source's conditions and appendices. Human review and clear tool definitions remain relevant. Source examples and framework names are deliberately omitted.
