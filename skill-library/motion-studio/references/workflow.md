# Editorial workflow

Write the central question before choosing a metaphor. Extract only necessary claims with source links and boundaries. Mark each visual as source depiction, illustrative example, or measured result. Never let an illustration silently become evidence.

Each shot needs a time range, viewer question, subject, start/end state, continuity, and sound cue.

## Two-direction test
Render two real keyframes from the same brief:
- Mechanism-first: begin with the object/state causing the problem; let the solution change that object.
- Consequence-first: begin with the user's question or observable failure; reveal the mechanism when it resolves ambiguity.
Change visual premise and hierarchy, not merely palette. Select one and record why. Do not build the full timeline until the mechanism reads in a still.

## Eight-to-ten-second proof
The proof must include the core state change and consequences, demonstrating object continuity, layering, timing hierarchy, transition logic, or sound. Review at normal speed and intended size before extending. Revise if movement merely decorates a title.

## Review
1. Editorial: every shot adds information; claims remain accurate; examples and measurements are distinguished.
2. Visual: clear focal point, readable type, no clipping, filler motifs, or repetitive equal-weight panels.
3. Motion: anticipation, action, settling and reading holds; object identity survives transformations.
4. Sound: deliberate start, transitions, continuity and ending; no clipping or accidental silence; mute test still works.
5. Technical: exact runtime, dimensions, fps, audio stream, poster and caption coverage.
6. Delivery: reviewers can inspect actual MP4/contact sheet and reproduce from locked source without private paths.

A render, lint pass, or contact sheet is evidence of a build, not a substitute for full-playback review.
